# ADR-0043: HTTPS and WSS to the SignalK server, its certificate pinned on first use

Status: **Proposed** (2026-11-21)

## Context
- **What a server with SSL does:** signalk-server with `ssl: true` serves HTTPS and WSS on `sslport` (3443 by default). Its plain port only answers with a redirect to https, and mDNS announces `_signalk-https._tcp` / `_signalk-wss._tcp` in place of `_signalk-http._tcp`. A display that speaks only HTTP can't use such a server at all.
- **The server's own certificate:** generated by signalk-server (`selfsigned` 2.4.1) when it has none.
  - It is self-signed (`CA:TRUE`), with CN `localhost` and a SAN that holds only a URI, no DNS name or IP.
  - It is signed with SHA-1, RSA 2048, valid for 10 years, 756 B DER.
  - mbedTLS 3.6 rejects it as a CA with flags `0x400c` (not trusted, CN mismatch, bad MD). No CA bundle can vouch for it, and no name check passes.
- **Who else connects:** a boat's server is reached by its LAN address. An attacker on the boat's Wi-Fi could pose as the server and collect the display's read/write token (ADR-0003). TLS protects the token only if the display checks *which* certificate it gets.
- **Memory:** a TLS session costs internal RAM for mbedTLS's buffers (16 KB in, up to 16 KB out) and the handshake. On boards without PSRAM (CYD, C3) that comes out of a budget already tight (ADR-0026: partial LVGL buffer, 6 recorded values).

## Decision
TLS lives in ESPHomeSignalK (`tls:` option, `components/signalk/tls_pin.h`; PR batuakan/ESPHomeSignalK#21). The ESPHelm runtime's own HTTP clients use the same trust.

- **Pin on first use.**
  - **First connection:** the display trusts the certificate it gets on its first TLS connection to a server. It stores the certificate's SHA-256 (of its DER encoding) next to the bound server, in ESPHome preference 10004 (`SavedTls`, apart from `SavedServer` so the older record keeps its size).
  - **Every later connection:** the certificate must match the pin. The check is a verify callback (`mbedtls_ssl_conf_verify`, installed through esp-tls's `crt_bundle_attach` with an empty CA chain). It hashes the depth-0 certificate and clears mbedTLS's own flags, so the name, the self-signature and SHA-1 don't matter: the exact certificate does.
  - **The host build:** OpenSSL fetches the certificate first, checks the pin, and then gives ixwebsocket that certificate as its only CA (`caFile` as PEM in memory, `disable_hostname_validation`).
- **A changed certificate is refused.**
  - **What the display does:** it disconnects, sends nothing more (no token, no hello), and keeps the cached layout. It logs both fingerprints.
  - **What the user sees:** the *Network* tab says the server presented another certificate and shows its fingerprint's start. *Forget server* (ADR-0026) clears the pin with the server, so the next server found is pinned anew.
  - **Configured host:** with `host:` in the YAML there is no *Forget server*. Its pin goes with a factory reset, like everything else the display saved.
- **Servers with SSL are preferred.**
  - **Discovery:** mDNS looks for `_signalk-https._tcp` beside `_signalk-http._tcp`; for the same server, TLS wins.
  - **No downgrade:** a display bound to a TLS server never follows the same server back to plain HTTP. A server that drops SSL must be forgotten first.
- **Configuration:** `signalk: tls:` is AUTO (no key: mDNS finds either, preferring TLS; `host:` means plain HTTP), `true` (`host:` over HTTPS/WSS) or `false` (plain only).
- **Boards without PSRAM stay plain.** `esphelm_cyd.yaml` and `esphelm_c3_compile_check.yaml` set `tls: false`. The P4, the Guition and the RLCD have TLS (AUTO).
- **The runtime's clients follow the server:**
  - **Covered:** layout, hello, firmware download (ADR-0036), metadata zones (ADR-0020).
  - **How:** their URLs come from `SignalK::base_url()`, and `server_tls.h` attaches the same verify callback (device) or pinned PEM (host).
  - **Chart tiles** go through the same base URL.
- **On the display:** the *Info* and *Network* tabs show *Security* (`HTTP`, `HTTPS, pinning`, `HTTPS`, `HTTPS, refused`). The *Network* tab also shows *Certificate*, the start of the pinned SHA-256 as `openssl x509 -fingerprint -sha256` prints it, so it can be compared with the server's.

## Consequences
- **Measured on the P4** (2026-11-21, signalk-server 2.37 with SSL, security on):
  - **Discovery and pinning:** it found the server with mDNS and pinned its certificate; the fingerprint matched openssl's.
  - **Timing:** the WSS stream connected about 250 ms after starting. Each HTTPS request took about 220 ms, handshake included (no session reuse).
  - **Memory:** free internal RAM was 325 KB with TLS and the stream open, 358 KB plain (stream not yet open). TLS costs about 33 KB of internal RAM, with `CONFIG_MBEDTLS_EXTERNAL_MEM_ALLOC` off.
  - **Flash:** the certificate-bundle option ESPHome turns off by default is required for `crt_bundle_attach`; with an empty bundle it adds no measurable flash.
- **Trust on first use has a window.** A server impersonated at the very first connection would be pinned instead. Approving the access request in the real server's admin UI narrows it: a fake server would have to forward that too. The fingerprint on the *Network* tab lets a careful user check it.
- **A new certificate needs a user.** Renewing or regenerating the server's certificate (also restoring a config without `ssl-cert.pem`) makes every display refuse it until *Forget server* on each, and a fresh approval if the token doesn't carry over. Deliberately so: the display can't tell a renewal from an attacker.
- **No CA-signed certificates.** A server with a real certificate (e.g. Let's Encrypt behind a proxy) is pinned the same way: renewing it every 90 days would mean forgetting the server each time. Accepting a CA chain is a possible later option.
- **Not covered yet:**
  - the Guition (S3) and the RLCD on hardware;
  - `CONFIG_MBEDTLS_EXTERNAL_MEM_ALLOC` on the PSRAM boards (would move mbedTLS's buffers out of internal RAM).
- **Testing:** the SDL e2e (section 16, `firmware/esphelm_sdl_tls.yaml`) runs against a real signalk-server with SSL. It pins, gets its token, says hello, fetches its layout and streams over TLS, then refuses a regenerated certificate. ESPHomeSignalK has its own `tools/e2e_tls.sh` and unit tests for the pin record and mDNS parsing.
